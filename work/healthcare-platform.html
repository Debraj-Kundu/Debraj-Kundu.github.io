01 / THE PROBLEM

As the product grew, the backend had to absorb far more traffic while keeping real-time features working and staying within NHS England and GDPR rules.

Two pressure points stood out: WebSocket connections that tied users to a single instance, and file uploads that pushed every byte through the API tier.

02 / THE ENGINEERING

Backend services were containerised and moved to Azure Kubernetes Service, so the API tier scales out across pods. Real-time messages go through Redis Pub/Sub, so any pod can deliver an event to any connected client: WebSockets scale horizontally instead of being pinned to one instance.

Uploads moved to a Shared Access Signature flow: the API issues short-lived, scoped tokens and clients upload straight to storage, with encryption, keeping file bandwidth off the API servers.

03 / THE RESULT

The platform scaled to 6M+ requests a day. The SAS pipeline cut bandwidth by 40% while keeping data encrypted and NHS England GDPR compliant.

DETAILS THAT MATTER
  • Scalability: stateless services behind Kubernetes, with real-time fan-out through Redis.
  • Cost: direct-to-storage uploads take heavy traffic off compute.
  • Security: short-lived, least-privilege SAS tokens; encryption in transit and at rest.
  • Compliance: designed within NHS England and GDPR requirements.
